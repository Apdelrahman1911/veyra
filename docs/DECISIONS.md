# Veyra decision record

Only consequential choices belong here. Each final decision needs evidence, alternatives, and consequences; research detail lives in the linked reports.

## D001 — Scope, access, and repository visibility (accepted)
The last user instruction overrides the earlier private default: create Veyra **public** when implementation begins. Use only free standard public-repository Actions runners and existing resources. All project files, temporary writes, cleanup and GitHub changes are confined to Veyra and kmpYT. No system configuration or unrelated repositories may change.

## D002 — Execution model and truthful evidence (accepted)
Use all ten useful slots (lead plus nine independent workstreams), explicitly requesting GPT-6 Astra / max for each subagent. The creation tool accepted those fields but provides no effective-runtime attestation. Report that limitation exactly. The formal Goal is active; no arbitrary token budget was assigned. Preserve state before limits/restarts and do not claim background work without an active mechanism.

## D003 — Research endpoint and navigation (accepted)
Nine source-linked studies and cross-review are complete; implementation starts now. [Music](research/music-ux.md), [podcasts](research/podcast-ux.md), and [design](research/design-accessibility.md) support independent save/download/queue semantics. Resolve the 3-vs-4-destination disagreement in favor of **Listen/Search/Podcasts/Library**, with distinct jobs rather than duplicate filters: genuine podcasts need visible Continue/Following/Add RSS. This is a reasoned product choice, not a claimed comparative usability study. Test narrow Arabic/large-text layouts; change presentation, not capability, if labels do not fit.

## D004 — Two saved contexts, one audio owner (accepted)
Cross-review exposed an ambiguous 'second queue' phrase and invisible cross-mode sleep timers. One coordinator owns two persistent contexts; browsing never switches playback. Occurrence IDs and tokened native events guard duplicates/races. Manual reordering explicitly disables shuffle and adopts edited displayed order; unshuffle never loses additions. Duration timer is global/visible and monotonic-elapsed; end-episode timer is episode-bound and prevents advance. Confirmed end, manual played flag, and last real position are independent. See podcast/media reports for counterexamples and tests.

## D005 — Sources and honest availability (accepted)
[kmpYT audit](research/kmpyt-audit.md) proves browsing/planning/downloading APIs, not musical album or podcast semantics. [Measured feasibility](research/integration-feasibility.md) found real approved YouTube metadata but LOGIN_REQUIRED/zero formats, genuine English/Arabic RSS, and a CC-licensed HPR episode. Use real kmpYT plus an independent genuine RSS adapter/no-key directory; label optional Commons Open music explicitly and retain recording-specific rights. Source restriction differs from no results/network/unsupported codec. No alternate identity/bypass or fixture substitution. The live YouTube gate stays unresolved until actually demonstrated.

## D006 — Conservative build and recoverable local persistence (accepted)
Use the known upstream baseline plus compatible released Compose, pinned in version control; disclose AGP/KGP tested-range caveat and verify actual builds. A Git submodule pins kmpYT without MavenLocal/global installation. Architect initially preferred SQLDelight; after comparing startup/build scope and small-client needs, accept V1 **atomic versioned JSON snapshots** with one writer, coalesced progress, staged replacement/backup, bounded parse and kill/reopen tests. This is persistent local storage, not an in-memory prototype. Do not silently reset damaged/newer-schema data; plan a measured SQLite migration if scale requires. [Architecture evidence](research/architecture.md).

## D007 — Native playback and runtime/license gates (accepted technical choice; distribution gated)
Media3/AVPlayer own native transport; shared coordinator owns business semantics. On desktop use raw JNA/libmpv runtime artifacts rather than MediaMP's Kotlin wrapper, avoiding an untested compiler upgrade. [Desktop experiments](research/desktop-runtime.md) establish codec/seek behavior with a null sink, not audible physical output. Force verified TLS; validate transfers because truncated WebM can still reach native EOF. Linux bundle requires Ubuntu24.04+ and GPL compliance. Veyra's newly authored code will use GPL-3.0-or-later to permit compliant combined desktop distribution; collect corresponding sources/notices. **kmpYT has no license:** owner asked explicitly for MIT approval; no upstream license edit or redistribution permission is assumed. Public binaries remain gated on resolving that permission and complete compliance. Desktop extraction helpers require a separately verified clean-machine installation/initialization strategy, not reliance on VPS tools.

## D008 — Downloads/background and free verification (accepted)
Progressive standalone files first. Native background executors do not inherit kmpYT safety merely by receiving its URL. RSS/HEAD lengths are advisory; real response length/ranges, strong source-scoped validators, decoded media and final-file hash determine Ready. Durable staging/reconciliation bridges the non-atomic file/store boundary. Respect iOS suspension: report NeedsForeground/Paused where source renewal/execution cannot continue; never promise unrestricted background work. Tests must deny **native player** network too after restart, not just mock Ktor. Use standard free public runners, logs/job summaries and public Releases; current artifact-storage allowance is not assumed free. [Mobile](research/mobile-audio.md) and [CI](research/verification-ci.md) detail remaining native/signing/host-isolation gates.
