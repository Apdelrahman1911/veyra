# Veyra decision record

Only consequential choices belong here. Each final decision needs evidence, alternatives, and consequences; research detail lives in the linked reports.

## D001 — Scope, access, and repository visibility (accepted)
The last user instruction overrides the earlier private default: create Veyra **public** when implementation begins. Use only free standard public-repository Actions runners and existing resources. All project files, temporary writes, cleanup and GitHub changes are confined to Veyra and kmpYT. No system configuration or unrelated repositories may change.

## D002 — Execution model and truthful evidence (accepted)
Use all ten useful slots (lead plus nine independent workstreams), explicitly requesting GPT-6 Astra / max for each subagent. The creation tool accepted those fields but provides no effective-runtime attestation. Report that limitation exactly. The formal Goal is active; no arbitrary token budget was assigned. Preserve state before limits/restarts and do not claim background work without an active mechanism.

## D003 — Research endpoint and navigation (accepted)
Nine source-linked studies and cross-review are complete; implementation starts now. [Music](research/music-ux.md), [podcasts](research/podcast-ux.md), and [design](research/design-accessibility.md) support independent save/download/queue semantics. Resolve the 3-vs-4-destination disagreement in favor of **Listen/Search/Podcasts/Library**, with distinct jobs rather than duplicate filters: genuine podcasts need visible Continue/Following/Add RSS. This is a reasoned product choice, not a claimed comparative usability study. Test narrow Arabic/large-text layouts; change presentation, not capability, if labels do not fit.

## D004 — Two saved contexts, one audio owner (accepted)
Cross-review exposed an ambiguous 'second queue' phrase and invisible cross-mode sleep timers. One coordinator owns two persistent contexts; browsing never switches playback. Occurrence IDs and tokened native events guard duplicates/races. Manual reordering explicitly disables shuffle and adopts edited displayed order; unshuffle never loses additions. Duration timer is global/visible and monotonic-elapsed; end-episode timer is episode-bound and prevents advance. Confirmed end, manual played flag, and last real position are independent. See podcast/media reports for counterexamples and tests.

## D005 — One central kmpYT media execution layer (accepted; user supersession)
The owner's architecture update replaces the previous independent RSS playback/download proposal. **Every supported music track, release/album, show/episode, and externally discovered playable item must resolve through kmpYT.** Discovery integrations may supply metadata only: obtain the complete accurate title and metadata, submit the **complete title** to kmpYT search, accept its **first ordered result**, then use that resolved result for playback plans and downloading. No title truncation, choosing a later result, independent RSS downloader, or hidden source fallback. Preserve both requested and resolved identities/metadata and disclose differing recordings. Collection/non-playable first results require explicit type-aware library handling or a truthful unsupported-result error, not silent filtering.

kmpYT owns central acquisition/execution contracts; Veyra owns native audio/session adapters, Room state, UI, and OS orchestration. Enhancements must be general-purpose, tested upstream, reviewed/merged, and pinned. Audit search, plans, formats, refresh and downloads **separately** for tracks, albums, shows and episodes; search support alone is not capability proof. [The existing audit](research/kmpyt-audit.md) and [live evidence](research/integration-feasibility.md) found YouTube metadata but LOGIN_REQUIRED/zero formats. Direct RSS helper playback is no longer a compliant end-to-end proof. No authorization bypass or fixture substitution; the real central listening gate remains unresolved.

## D006 — Complete Room Multiplatform persistence (accepted; user supersession)
**Room replaces JSON snapshots**, not a blob table or temporary store. Use a normalized relational schema for artists, tracks, albums/releases, playlists, podcasts, episodes, source-resolution provenance, independent music/podcast contexts, occurrence-ordered queues/shuffle/history, playback progress, downloads/attempts/recovery, settings and offline/local references. Enforce foreign keys, uniqueness, transactions and serialized/coordinated writes; use versioned exported schemas, explicit safe migrations, integrity checks and crash-recovery/reconciliation tests. Never silently reset a corrupt or newer-version database. `AppSnapshot` may remain only an in-memory UI projection, not persistent JSON.

Room2.8.5 + bundled SQLite2.6.2 + KSP2.2.21-2.0.4 are selected after checking published Android/JVM/iOS artifacts; all targets still require compilation and database tests. Keep the known Kotlin/Compose baseline and reproducibly pinned kmpYT submodule; disclose the AGP/KGP tested-range caveat. This is complete required architecture, not an MVP tradeoff. [Architecture evidence](research/architecture.md).

## D007 — Native playback and runtime/license gates (accepted technical choice; distribution gated)
Media3/AVPlayer own native transport; shared coordinator owns business semantics and managed crossfade decks (D009), using central kmpYT execution (D005). On desktop use raw JNA/libmpv runtime artifacts rather than MediaMP's Kotlin wrapper, avoiding an untested compiler upgrade. [Desktop experiments](research/desktop-runtime.md) establish codec/seek behavior with a null sink, not audible physical output. Force verified TLS; validate transfers because truncated WebM can still reach native EOF. Linux bundle requires Ubuntu24.04+ and GPL compliance. Veyra's newly authored code uses GPL-3.0-or-later; retain corresponding sources/notices. **The kmpYT owner explicitly authorized MIT adoption on 2026-11-06**, subject to contribution/dependency review. Official MIT license is locally committed with accurate attribution at `e8754184b37b8c30fa89956908f09cda7f56732e`; baseline contribution/dependency review is complete with no conflicting grant found. The former licensing-permission/audit blocker is resolved. Remote publication, final pin, exact binary inventories, notices and corresponding-source compliance remain delivery gates. See [licensing verification](verification/licensing.md). Desktop extraction helpers require verified clean-machine initialization/packaging, not reliance on VPS tools.

## D008 — Complete persistent downloads and native orchestration (accepted; user supersession)
Implement the full system now: Room-backed persistent queue and attempt records, duplicate prevention, bounded parallel execution where supported, accurate progress, pause/resume/cancel/retry/backoff, resumable checkpoints, URL renewal, recovery after process/device restart, storage accounting/cleanup, safe temporary files and atomic finalization. **kmpYT executes all acquisition/downloads**; Veyra and native workers orchestrate, validate and reconcile rather than implement competing transfers. The previous progressive-standalone-first limitation is rejected. Verify the library's supported representations and extend missing general-purpose capabilities upstream.

Real response lengths/ranges, strong scoped validators, decoded media and final-file hashes determine Ready; publisher sizes are advisory. Durable finalization/reconciliation bridges filesystem/database transactions. Android foreground/WorkManager, iOS permitted task/background APIs and desktop lifetime scheduling must preserve this boundary. On iOS report NeedsForeground/Paused whenever source renewal or execution cannot legally continue; no unrestricted-background promise. Tests deny **native player** network after restart, not only Ktor. Standard free public runners only, with logs/job summaries and public Releases; artifact-storage allowance is not assumed free. [Mobile](research/mobile-audio.md) and [CI](research/verification-ci.md).

## D009 — Complete music crossfade (accepted; new user requirement)
Settings → Playback provides persistent enable/disable and at least 2/3/4/5-second durations (bounded custom duration if practical). Consecutive music tracks overlap using accurately coordinated native decks and equal-power fade-out/fade-in curves. One authoritative coordinator manages both; podcasts never crossfade automatically. Account for mixer headroom/clipping, short/unknown durations, disabled/changed settings, seek, manual track/queue changes, focus/interruption/route changes, next-source failure, and stop/restart without uncontrolled duplicate audio or silence. Disabling restores ordinary transitions. Automated clock/state/envelope/interruption tests and actual native output tests are required. **Physical-device audible-output verification is explicitly mandatory** and cannot be replaced by mocks, simulators, or a null sink. Missing hardware evidence leaves the Goal incomplete.
